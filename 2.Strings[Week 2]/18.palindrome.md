The **Valid Palindrome** problem is one of the most common string interview questions. It tests your understanding of:

* Two pointers
* String manipulation
* Character validation
* Time and space complexity

It is frequently asked by companies because the solution is simple but reveals whether a candidate can write clean, bug-free code.

# Problem Statement (LeetCode 125)

Given a string `s`, determine if it is a palindrome, considering only alphanumeric characters and ignoring cases.

### Example 1

```
Input:
"A man, a plan, a canal: Panama"

Output:
true
```

Because after removing special characters:

```
amanaplanacanalpanama
```

which reads the same from both ends.

---

### Example 2

```
Input:
"race a car"

Output:
false
```

---

## Interview Intuition

The interviewer wants to know whether you can:

* Ignore spaces
* Ignore punctuation
* Ignore uppercase/lowercase
* Compare efficiently

Instead of creating another cleaned string, we can compare characters directly from both ends.

This leads to the **Two Pointer** approach.

---

# Brute Force

### Idea

1. Remove all non-alphanumeric characters.
2. Convert to lowercase.
3. Reverse it.
4. Compare.

### Complexity

```
Time : O(n)
Space: O(n)
```

Good enough but not optimal.

---

# Optimal Approach (Two Pointers)

Suppose

```
"A man, a plan, a canal: Panama"
```

```
l = 0
r = n-1
```

Move left until it points to a letter or digit.

Move right until it points to a letter or digit.

Compare.

If equal

```
l++
r--
```

Else

```
false
```

Continue until pointers cross.

# Java Solution

```java
class Solution {
    public boolean isPalindrome(String s) {

        int left = 0;
        int right = s.length() - 1;

        while (left < right) {

            // Skip non-alphanumeric from left
            while (left < right && !Character.isLetterOrDigit(s.charAt(left))) {
                left++;
            }

            // Skip non-alphanumeric from right
            while (left < right && !Character.isLetterOrDigit(s.charAt(right))) {
                right--;
            }

            // Compare lowercase characters
            if (Character.toLowerCase(s.charAt(left))
                    != Character.toLowerCase(s.charAt(right))) {
                return false;
            }

            left++;
            right--;
        }

        return true;
    }
}
```


# Common Interview Mistakes

### 1. Forgetting lowercase conversion

Wrong

```java
'A' != 'a'
```

Correct

```java
Character.toLowerCase()
```

---

### 2. Forgetting to ignore punctuation

Wrong

```
"A,"
```

`,` should be skipped.

---

### 3. Pointer out-of-bound

Always write

```java
left < right
```

inside skip loops.

---

### 4. Creating unnecessary strings

Avoid

```java
replaceAll(...)
```

because it creates extra memory.

Interviewers generally prefer the two-pointer solution.
